# Transfer protocol contract
Protocol v1 endpoints: GET /v1/commands/next?realm=SR1|SR2 and POST /v1/commands/result. Inventory command fields: op_id, kind, item, count, save_id. Current transfer scope is Pink IDs, distinct realms, count 1–30 and caller-owned logical idempotency_key.
Ledger states: PREPARED -> LOCKED -> ESCROWED -> COMMITTED; pre-escrow abort; refund path ESCROWED -> REFUND_PENDING -> REFUNDED. Do not omit REFUND_PENDING. Mutation success requires expected delta, applied/persisted/verified=true, uncertain=false, exact identity binding, save filename and SHA-256.
BridgeHost Python HTTP loopback command mailbox, realm-bound authentication, heartbeats and process/session provenance. Operations query/remove/add/lab_give; op_id is stable deduplication identity. At-least-once delivery is NOT exactly-once external execution. Strict durable plugin INTENT before mutation and DONE receipt, host ledger, receiver dispatch/refund fences and native persisted receipts protect recovery. Bind exact save/realm/process and item/count; unresolved mutation cannot be retried as a new logical operation or refunded across dispatched receiver work. Pink slime/plort bidirectional runtime baseline exists; generic exclusive species transfers/registration not proven. See existing bridge/host/server.py, bridge/transfer/ and mods/shared/BridgeCommands.cs; Cloud must not rewrite these.
